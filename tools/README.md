# Development tooling

`node tools/localise.mjs --check` extracts Android source strings/plurals and fails for missing, structurally invalid or stale-source drafts and detected hardcoded UI text. It audits all 19 locales independently of human approval. `--release` enforces the configured translation policy; the owner has waived human translation review. Missing text, stale sources, invalid placeholders and incomplete plurals still fail. Source fingerprints, indexed placeholders, protected terms and per-locale plural categories are checked. Non-translatable labels are excluded; Android/XML escapes are decoded before auditing.

`node tools/localise.mjs --check --generate` validates all locale bundles before generating shared resources under `app/src/main/res/values-b+.../` and `xml/locales_config.xml`. `--preview` remains an alias. All Android variants include the 19 locales without a draft notice. The owner waiver is recorded in `config/locales.json`; acceptance under that policy does not fabricate human approval. The separate `com.trailnest.app.draft` package remains available for isolated review fixtures. See `docs/LOCALISATION.md` for provenance and review rules. Keep generated resources in sync with JSON; tooling tests compare every string/plural in all 19 bundles.

To refresh non-critical drafts through an operator-configured service, use `--translate=de` (or another registry tag) with development-only `TRAILNEST_TRANSLATION_URL` (HTTPS) and `TRAILNEST_TRANSLATION_TOKEN`. The endpoint accepts `{source,target,key,text,protectedTerms,terminology}` and returns `{translatedText}`. Responses are cached by endpoint, content and glossary; tokens are never written. Current source hashes preserve existing entries; changed sources create new unreviewed drafts. This option excludes safety-critical keys and does not translate plurals automatically. The committed seed drafts and their public-web provenance are described in `docs/LOCALISATION.md`; generation/checking needs no external service. Human approval requires `reviewed:true`, a reviewer and ISO review date, matching source fingerprints, any required safety reviewer, and explicit locale approval in the registry. Current entries and registry flags all remain unreviewed.

`node --test tools/tests/*.test.mjs` runs ten tests covering extraction, XML escaping, placeholders, review/source invalidation, locale qualifiers, UI literal detection, all shared locale resources and review-waiver validation, plural categories and actual Room migration SQL. Requires Node 24 with experimental `node:sqlite`. Android instrumentation checks real Room migration, photo handling and UI, but requires a connected device.

`node tools/editorial.mjs validate` checks the empty initial catalogue or future route records. It rejects published records without a named reviewer, review date, explicit human approval, source, licence and valid geometry. `retire` records the operator and reason in revision history. This is local validation/retirement tooling, not a hosted editorial CMS or partner authorization system.

`tools/capture-android.ps1` captures real app screens from a connected development device. It refuses to label captures as marketing-ready. No route examples are seeded. A physical Fire device or working emulator is needed.
