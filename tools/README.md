# Development tooling

`./tools/build-production.ps1 -Checks` builds the normal production APK using the owner-authorized Windows identity outside Git, with a current-user DPAPI password. It creates no key, restores process environment variables afterward and checks the APK v2/v3 signatures against `config/production-signing.json`. Production purchasing remains disabled. This command does not upload, submit, install on a device or change LAT tests. A local backup is not an independent disaster-recovery backup: preserve the key and a recoverable password before replacing this computer.

`node tools/localise.mjs --check` extracts Android source strings/plurals and fails for missing, structurally invalid or stale-source drafts and detected hardcoded UI text. It audits all 22 locales independently of human approval. `--release` enforces the configured translation policy; the owner has waived human translation review. Missing text, stale sources, invalid placeholders and incomplete plurals still fail. Source fingerprints, indexed placeholders, protected terms and per-locale plural categories are checked. Non-translatable labels are excluded; Android/XML escapes are decoded before auditing.

`node tools/localise.mjs --check --generate` validates all locale bundles before generating shared resources under `app/src/main/res/values-b+.../` (Indonesian uses Android’s legacy `values-in` qualifier) and `xml/locales_config.xml`. `--preview` remains an alias. All Android variants include the 22 locales without a draft notice. The owner waiver is recorded in `config/locales.json`; acceptance under that policy does not fabricate human approval. The separate `com.trailnest.app.draft` package remains available for isolated review fixtures. See `docs/LOCALISATION.md` for provenance and review rules. Keep generated resources in sync with JSON; tooling tests compare every string/plural in all 22 bundles.

To refresh non-critical drafts through an operator-configured service, use `--translate=de` (or another registry tag) with development-only `TRAILNEST_TRANSLATION_URL` (HTTPS) and `TRAILNEST_TRANSLATION_TOKEN`. The endpoint accepts `{source,target,key,text,protectedTerms,terminology}` and returns `{translatedText}`. Responses are cached by endpoint, content and glossary; tokens are never written. Current source hashes preserve existing entries; changed sources create new unreviewed drafts. This option excludes safety-critical keys and does not translate plurals automatically. The committed seed drafts and their public-web provenance are described in `docs/LOCALISATION.md`; generation/checking needs no external service. Human approval requires `reviewed:true`, a reviewer and ISO review date, matching source fingerprints, any required safety reviewer, and explicit locale approval in the registry. Current entries and registry flags all remain unreviewed.

`node --test tools/tests/*.test.mjs` runs nineteen tests covering extraction, XML escaping, placeholders, review/source invalidation, locale qualifiers, UI literal detection, all shared locale resources and review-waiver validation, plural categories, actual Room migration SQL, store-copy limits, localized screenshot evidence and stale release-audit rejection. Requires Node 24 with experimental `node:sqlite`. Android instrumentation checks real Room migration, photo handling and UI, but requires a connected device.

`node tools/editorial.mjs validate` checks the empty initial catalogue or future route records. It rejects published records without a named reviewer, review date, explicit human approval, source, licence and valid geometry. `retire` records the operator and reason in revision history. This is local validation/retirement tooling, not a hosted editorial CMS or partner authorization system.

`tools/capture-android.ps1` captures real app screens from a connected development device. It refuses to label captures as marketing-ready. No route examples are seeded. A physical Fire device or working emulator is needed.

`node tools/release-gate.mjs` now reruns translation validation against current sources, checks required initial languages in `config/locales.json`, audits storefront copy and all supported app locales’ screenshot sets, and writes `artifacts/marketing-audit.json` plus `artifacts/release-gate.json`. A nonzero exit is expected until release prerequisites are fulfilled. In-app language coverage does not prove localized store-copy or screenshot coverage. Eight screenshots per app locale are the owner requirement; Amazon allows 3–10 tablet screenshots.

Store copy uses `marketing/listing-<locale>.json`, plain text, a 2,000-byte UTF-8 short description, a 4,000-character long description and 3–5 feature bullets. Drafts stay blocked. Each public PNG capture in `marketing/screenshots.json` needs `locale`, matching `uiLocale`, a distinct planned `screenId`, current Android `version`, `status: "reviewed"`, a `marketing/` file path and its SHA-256. The audit checks path containment, PNG header dimensions and file hash; visual fidelity, translation meaning and actual functionality still require review. Current 0.8.6 exports have agent visual review, with human approval explicitly false. No Amazon upload or commercial-release approval is implied.

## Reproduce localized store assets

Run `node tools/prepare-marketing.mjs` to validate and generate all 22 listing files and isolated native fixture assets from `marketing/localized-copy.json` and the current dictionaries. Build/install the translationPreview and its test APK on a development device, then run `MarketingCaptureDeviceTest`. It checks all 261 installed strings per locale before capturing eight real UI scenes, with text-overflow checks and localized example data. Pull only its `marketing-captures` directory, then run `node tools/export-marketing.mjs <pulled-directory>`. The exporter preserves the PNG bytes and requires current version, hashes, locale, headline, installed-resource count and content fingerprints. It deliberately resets visual review: inspect all captures before marking them reviewed.

`marketing-content.mjs` fingerprints UI strings/plurals, example names, headlines and version. Same-version wording changes invalidate old screenshot evidence. Indonesian keeps canonical `id` in preferences/metadata but generates `values-in` for correct pre-Android-15 resource selection. Regression tests cover the alias and stale captures.
