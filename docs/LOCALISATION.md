# Active localisation — Android 0.8.6

All 22 configured Android locales are **active in every Android variant**: en-US, en-GB, en-AU, en-IN, fr, de, it, es, es-MX, pt-BR, pt-PT, nl, pl, sv, ja, ar, hi, zh-Hans, ko, zh-Hant, tr and id. Each bundle contains 261 strings and four plural resources. On 23 October 2026 the owner waived the human translation-review requirement. The app no longer shows a translation draft notice, and translation release checks accept structurally valid, current bundles under that policy. Existing provenance and `reviewed:false` history remain accurate; no human sign-off is invented. Regional English copies and Mexican Spanish retain their original provenance.

The migration covers navigation, discover/coverage/pack screens, route progress and spoken status, settings/privacy, journal summaries, validation/errors, system sharing text, accessibility image descriptions and default checklist items. Brand names, internal navigation IDs, protocol fields, GPX XML, ISO date formats, country metadata and the existing English voice-command recognition vocabulary are not translated as display text. Country names displayed in coverage use the selected app locale. Human-entered names, notes, contacts and renamed/custom checklist items are never translated. Unchanged legacy default checklist labels retain their IDs/check states and now resolve through locale resources; explicit renames remain literal user text.

Displayed distance units and number formatting use the resource locale. Journal distance entry accepts decimal commas and local digits, rejects grouping/mixed separators, and preserves the exact stored distance when an unchanged formatted value is saved. Dates and return-time entry retain their explicitly labelled ISO formats and left-to-right input direction. Shared coordinates and return timestamps use Unicode directional isolates. Directional coverage arrows mirror in RTL layouts.

Navigation uses a scrollable rail on sufficiently wide layouts at normal font sizes and a full-width, scrollable menu on narrow or large-font layouts. Labels grow vertically. Action rows wrap, panel padding adapts, and font padding/heading line spacing accommodate script marks. Letter spacing is disabled for Arabic, Hindi and East Asian section labels. The system font scale is respected.

## Files and preview

- `app/src/main/res/values/`: complete English fallback text for unsupported device languages and untranslated non-display identifiers.
- `localisation/source.json` and `plurals-source.json`: decoded translation source, generated from all default values XML files; non-translatable brand/build labels are excluded.
- `localisation/<tag>.json`: text/forms, source SHA-256 fingerprint, provenance and review history. A claim of human approval still requires actual reviewer metadata (including safety review where marked); the owner's policy does not require that approval for translation acceptance.
- `app/src/main/res/values-b+.../` and Indonesian `values-in/`: generated active Android resources shared by debug, release, LAT and translation-preview builds, retaining region/script distinctions, including Portuguese variants and Simplified Chinese.

Run `node tools/localise.mjs --check --generate --release` (`--preview` remains a compatible generation alias), then build the desired variant. All variants share the 22-target locale configuration. Settings → App language offers all 22 locales by native name and Use device language. AndroidX AppCompat persists explicit selection on API 26–32 (including older Fire OS) and delegates to Android per-app language settings on API 33+. MainActivity uses AppCompatActivity so locale changes recreate the activity and update Compose resources/RTL; saved page/form state is retained by the existing rememberSaveable controls. The separate **TrailNest Draft** development package (`com.trailnest.app.draft`, `0.8.6-draft`) remains available for isolated synthetic tests. Its package/build name is unrelated to the removed translation notice. There is no runtime translation service. Language names are generated from Android locale metadata; the two picker labels are agent-authored for all 22 bundles with provenance recorded and no claim of human approval. ContextCompat resolves non-activity strings for checklist defaults, recording notifications, errors and saved recording notes. The previously submitted 0.8.1 LAT APK remains English-only; source changes do not replace an already submitted binary or certify additional Amazon listing languages.

## Repeatable device layout matrix

Build the isolated test target with `gradlew.bat :app:assembleTranslationPreview :app:assembleTranslationPreviewAndroidTest -PtrailnestTestBuildType=translationPreview --offline --max-workers=2`. Install the preview APK and its `androidTest/translationPreview` test APK. Run `adb shell am instrument -w -e class com.trailnest.app.LocaleLayoutDeviceTest com.trailnest.app.draft.test/androidx.test.runner.AndroidJUnitRunner`. Add `-e layoutSmoke true` before the runner for Arabic/German at 200% first.

The matrix uses actual app composables with synthetic fixtures, configured Android view contexts, all 22 locales, 360×640/800×640 dp panes and 100%/200% fonts: 88 configurations. Both panes fit the connected tablet in either orientation. Width/height assertions verify the requested sizes. Configuring the hosting Android view makes locale/font settings reach separate dialog windows as well as the main composition. It checks navigation direction/reachability, text measurement overflow, main screens, coverage, journal editing, sharing and recording review. It writes `layout-checks/matrix.json` and selected device screenshots under the draft app's external files directory.

The harness does not change system locale, font, rotation or timeout settings and does not use the normal app's database. Its temporary draft test windows can display above the PIN lock and keep the screen on; the device stays locked, and those window flags disappear with the activity. Normal debug tests do not show windows above the lock; they require an unlocked device. Normal debug instrumentation skips this draft-only matrix. Navigation retains unsaved per-page state while its compact menu is open; the recording UI test checks that an entered title survives opening/closing it. See `VERIFICATION.md` for executed results and limits; these checks do not approve translation meaning, spoken output or comprehensive accessibility.

The Settings part of the matrix also opens the language dialog, checks the selected device-default radio row, scrolls every configured option into view, audits target sizes/labels and dismisses it. Text overflow checks include all native names and translated picker labels at both font sizes and widths. `LanguagePickerDeviceTest` separately uses the real `MainActivity` in the isolated preview package to select all 22 languages, verify Android resources and RTL after recreation, check application-context strings, retain Settings during language-triggered recreation, and restore device default. Run it with `adb shell am instrument -w -e class com.trailnest.app.LanguagePickerDeviceTest com.trailnest.app.draft.test/androidx.test.runner.AndroidJUnitRunner`. It restores the original app-language choice in cleanup and does not change the system language. Process-restart persistence is checked separately with force-stop/relaunch. The owner resumed TrailNest Kindle testing on 24 October. Version 0.8.5 passed all 76 layout configurations, both language/notification device tests and French/device-default process-restart checks on KFTRWI/API 28; see VERIFICATION.md for evidence and OS limits. `LanguageNotificationDeviceTest` uses native Android accessibility controls and normal lifecycle timing to check cold and warm recording-notification intents, switching to French/German afterward, and retaining Settings through locale recreation. The app preserves the launch Intent and records initial-navigation handling in saved activity state; fresh onNewIntent events always open recording.

Implementation follows [Android's per-app language guidance](https://developer.android.com/guide/topics/resources/app-languages): `AppCompatActivity`, `AppCompatDelegate.setApplicationLocales` and the disabled `AppLocalesMetadataHolderService` with `autoStoreLocales=true`. No new language network service or login is introduced. API 33+ framework synchronization follows that AndroidX API; physical evidence is recorded per tested device, not inferred for every OS version.

Non-English seed drafts were generated through Google's public translation web interface using only English resource text from this repository. Core action labels received agent adjustments, not human linguistic review. Regional English copies are labelled as regional drafts. No journal entries, photos, contacts, GPS data, credentials or private files were submitted. The public web interface is not a production integration or a required build dependency; normal generation/checking works offline with committed drafts. The existing explicitly configured HTTPS translation-endpoint option remains available for future draft updates.

The five accessibility additions in Android 0.6 are agent-authored: contextual action formatting, rating descriptions, expanded/collapsed state and route geometry descriptions. Their original review-related provenance remains historical; the current owner policy waives linguistic review, without claiming assistive-technology acceptance. Repeated action labels combine translated actions with literal user-entered names; those names are not sent to a translation service.

## Checks and translation policy

`node tools/localise.mjs --check` fails on missing text, source changes, placeholder/protected-term problems or detected hardcoded UI strings. `--generate` validates every locale before writing shared resources and the locale configuration. `node --test tools/tests/*.test.mjs` verifies XML round-tripping, all 22 bundles and their generated resources, plural categories, placeholder preservation, source-change invalidation, translation-policy enforcement and shared locale activation. Synthetic device tests check the `.draft` application ID for isolation, independently of the translation policy. The scanner detects known UI/message call patterns; it is not a complete Kotlin semantic parser. Source review also checked remaining literal usage.

`config/locales.json` records `translationPolicy.humanReviewRequired:false` and the owner's waiver decision/date. Report `accepted` and `translationReady` describe acceptance under that policy; `approved` describes actual human-review evidence and remains false. Restoring a review requirement makes unreviewed entries fail acceptance again. A changed English source invalidates translations regardless of the waiver. Missing text, protected terms, placeholders, plurals and hardcoded UI text remain checked.

`node tools/localise.mjs --release` now passes for all 22 current bundles. The overall release gate no longer blocks on human translation review; unrelated route licensing, billing acceptance, signing and other production prerequisites remain in place. The companion website remains the separate English 0.1 preview.

Android 0.8 adds ten agent-authored billing strings per locale for annual terms, restore, pending/checking/unverified states, verification deadlines and the current geometry-pack benefit. They follow the same translation policy. Amazon supplies the actual displayed price; it is not hardcoded or machine-translated. Real LAT billing acceptance remains separate from translation checks.

### Indonesian resource selection regression

The first all-string native check exposed English fallback for canonical `id` on Fire API 28 when resources used `values-b+id`. A regression test first reproduced the wrong generated qualifier. Android retains the legacy `in` resource language code: generation now uses `values-in`, while preferences, locale config and store assets retain canonical `id`. Generation removes only its stale generated `values-b+id/strings.xml`. The focused device repro then passed all 261 installed strings and eight captures; the final 22-locale capture run passed the same checks for every locale. This is verified on the connected Fire, not inferred API 33+ acceptance. See [Android Locale documentation](https://developer.android.com/reference/java/util/Locale).

The final 0.8.6 KFTRWI/API 28 run passed all 88 layout configurations, both language/notification tests, the 26-case seven-state billing UI matrix and all 12 new-language keyboard configurations. No layout failures were recorded. [Sanitized evidence](../artifacts/localisation-device-0.8.6.json). The normal Amazon-installed app remains 0.8.5-lat/code 13; Test 1 was unchanged.
