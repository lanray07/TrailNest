## Fixes in this review

Corrected stale catalog/LAT blockers in README and setup documentation, retained dated historical observations, and made the acceptance table distinguish passed scenarios from untested cases. Updated English draft copy for actual recording, journal/photos, language support, limited voice commands and the distinction between offline geometry and basemaps. Replaced the eight unsupported marketing headlines with implemented features. These are drafts, not completed localized screenshot assets.

The release gate now reruns current translation validation and writes [marketing coverage](../artifacts/marketing-audit.json) alongside [release failures](../artifacts/release-gate.json). Store copy checks include UTF-8 byte limits and plain text; screenshots require distinct planned scenes, current app version, matching UI locale, existing PNG dimensions and a matching hash. Header/hash checks do not prove visual quality or truthful provenance; review remains required. No release evidence approval flag was set.

Production signing can now be configured without editing source or embedding credentials. With all four environment variables absent, the normal release remains unsigned; partial or unavailable-keystore configuration fails before packaging. The signed build path was exercised with a disposable QA-only RSA key: APK v2/v3 verification passed, LAT did not inherit that signing configuration, and the key and signed QA output were removed before restoring the unsigned release output. This does not supply or approve the production identity.

## Checks and primary references

Current command outcomes are recorded in [the dated check summary](../artifacts/amazon-release-review-2026-10-29.json). `node tools/release-gate.mjs` intentionally returns exit 1 while the above requirements remain open. Its failures are release blockers, not a claim that the unit tests or APK compilation failed.

Amazon's [presubmission checklist](https://developer.amazon.com/docs/app-submission/presubmission-checklist.html) calls for functional testing, accurate privacy declarations, appropriate images and any required third-party rights. Its [Appstore Details guide](https://developer.amazon.com/docs/app-submission/appstore-details.html), checked 29 October 2026, specifies a 2,000-byte short description, 4,000-character long description, 3–5 feature bullets and 3–10 tablet screenshots. The gate's eight-screen requirement comes from the owner, rather than an Amazon minimum.
